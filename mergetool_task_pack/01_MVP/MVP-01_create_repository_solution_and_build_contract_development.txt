# MVP-01 Development Task
## Headline
Create repository, solution, deterministic build contract, and project boundaries


## Objective
Create the smallest credible solution foundation without implementing comparison behavior yet.

## Developer instructions
Create the solution and projects defined in `00_ARCHITECTURE_GUARDRAILS.txt`. Target `net10.0-windows` for the WPF application and compatible `net10.0` libraries where Windows APIs are not needed.

Create at minimum:
- `global.json` pinning the SDK installed on the machine.
- `Directory.Build.props` enabling nullable reference types, implicit usings, deterministic builds, warnings-as-errors for new code where practical, and analyzers available in the SDK.
- `Directory.Packages.props` with Central Package Management enabled; do not add package versions outside it.
- solution file, root README, `.editorconfig`, `.gitignore`, `build.ps1`, `test.ps1`, `clean.ps1`.
- project reference graph that follows the guardrails exactly.
- `docs/DEPENDENCIES.md`, `docs/architecture/README.md`, `docs/task-reports/`, and `docs/defects/` directories.
- a minimal WPF shell that launches and displays product name plus two disabled navigation entries: File Compare and Folder Compare.
- minimal test projects using MSTest with one smoke test per non-WPF project.

Do NOT add AvalonEdit, a diff package, generic DI, logging framework, or comparison stubs that pretend functionality exists.

## Acceptance criteria
- A clean checkout builds and tests in Debug and Release using only the listed CLI tools.
- The WPF shell launches.
- Project reference direction matches the architecture guardrails.
- Every direct dependency is documented, even if only SDK-provided.

## Drift prevention
This is foundation only. No actual comparison UI, file loading, folder scanning, or merge behavior belongs here.

## Mandatory completion evidence
- Add/update automated tests for the change.
- Run Debug and Release build/test commands.
- Create the required development report under `docs/task-reports/`.
- Do not start the next task until the paired testing task has passed.
