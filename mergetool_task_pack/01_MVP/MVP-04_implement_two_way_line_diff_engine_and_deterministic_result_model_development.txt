# MVP-04 Development Task
## Headline
Implement 2-way line diff engine and deterministic result model


## Objective
Produce reliable line-level comparison results independent of WPF and suitable for later presentation and merge operations.

## Developer instructions
Implement in `MergeTool.Text`:
- `ITextDiffEngine` and one concrete line-based implementation.
- `TextComparisonOptions` with only explicit MVP defaults; no ignored-rule functionality yet.
- `TwoWayTextComparisonResult` containing input document/session identities, input document revisions, ordered `DiffBlock` collection, and summary counts.
- `DiffBlock`: deterministic ordinal/ID, `DiffBlockKind` (`Equal`, `Inserted`, `Deleted`, `Modified`), `LineRange` for both sides, and safe source anchors.
- a `LinePair`/alignment representation if needed by renderer and merge planner.

Algorithm policy:
- It may use an internally implemented algorithm or optional DiffPlex adapter only after licence entry/central version pin.
- It must return a deterministic result for the same inputs.
- It must classify obvious replacement regions as `Modified` where a meaningful line pairing exists; it may fall back to adjacent delete+insert only when pairing is ambiguous, and tests must document that behavior.
- It must handle empty files, final newline differences, repeated lines, multi-block changes, and large but ordinary text without recursion overflow.

Do not calculate intraline segments, regex options, moved blocks, or UI render data beyond the stable block/range model.

## Acceptance criteria
- All core diff tests assert exact line ranges/block order, not merely a difference count.
- Result objects include enough source/target range information to later plan a manual copy safely.
- The engine has no WPF/AvalonEdit dependency.

## Drift prevention
Do not create an editor-facing control, custom visual renderer, or generic algorithm plug-in system. One interface and one tested implementation are enough.

## Mandatory completion evidence
- Add/update automated tests for the change.
- Run Debug and Release build/test commands.
- Create the required development report under `docs/task-reports/`.
- Do not start the next task until the paired testing task has passed.
