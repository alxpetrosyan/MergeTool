# MVP-05 Development Task
## Headline
Implement editable comparison sessions, presentation mapping, and stale-result contract


## Objective
Bridge raw text comparison results to UI workflows without polluting the diff engine or enabling unsafe merge actions.

## Developer instructions
Implement in `MergeTool.Application`:
- `TextDocumentSession`: document snapshot/current editable text, document revision, dirty state, read-only state, original file identity/metadata.
- `TwoWayComparisonSession`: left/right document sessions, latest result, result request ID, comparison status, diagnostics, current selected block ID.
- `ComparisonPresentationMap`: maps source line indices to block IDs and exposes scroll/navigation anchors for both sides.
- `RecompareAsync` orchestration that uses cancellation/request IDs and only applies the newest completion.
- edit notification method: when a pane's text is changed, increment the matching document revision, mark dirty, mark comparison stale, and disable block navigation/merge until recompare completes.
- `MergePrecondition`: stores comparison revision, source/target document revision, target range, source range, and source/target text fingerprints needed to reject a stale operation.

MVP visualization contract:
- Source documents remain real, unpadded text in each pane.
- Do not insert blank display lines into document content.
- Presentation map supports a safe scroll anchor for any block. For a missing counterpart, anchor to the corresponding block boundary in the other document.
- UI will render semantic colour overlays from block ranges; it must not discover differences by rescanning editor text.

Add orchestration tests: stale request discarded, editing invalidates old result, recompare restores action eligibility, selected block is cleared/rebound safely when result changes, and presentation map handles insert/delete boundaries.

## Acceptance criteria
- A merge action can be proven invalid after any relevant edit or recompare.
- The app has one place responsible for comparison lifecycle and stale-result handling.
- Presentation mapping has tests for every block kind.

## Drift prevention
No WPF controls, AvalonEdit types, fake padding lines, live automatic compare-on-every-keystroke, or undo implementation here.

## Mandatory completion evidence
- Add/update automated tests for the change.
- Run Debug and Release build/test commands.
- Create the required development report under `docs/task-reports/`.
- Do not start the next task until the paired testing task has passed.
