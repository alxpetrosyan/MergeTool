# MVP-07 Development Task
## Headline
Implement 2-way file comparison workspace, semantic rendering, and scroll mapping


## Objective
Make the File Compare workspace visibly useful: open two text files, compare them, inspect colour-coded blocks, and scroll safely between panes.

## Developer instructions
Implement file workflow commands:
- choose left file / choose right file
- reject the same normalized file path on both sides with a clear message
- load both files asynchronously via `TextDocumentLoader`
- do not open `NotTextForThisProduct` files as an unsupported binary comparison; show a clear diagnostic
- compare/recompare via `TwoWayComparisonSession`

Use two AvalonEdit panes bound to the current editable document text. Implement:
- source line numbers
- fixed built-in semantic styles for equal/inserted/deleted/modified blocks
- current-file path, encoding, line-ending, dirty/read-only indicators
- status summary with difference counts and stale/compare state
- synchronized vertical scrolling based on `ComparisonPresentationMap`, with a reentrancy guard
- semantic rendering using WPF/AvalonEdit renderer adapters only; no text rescanning to infer blocks
- recompare button enabled after stale edits

MVP does not require vertical blank-line padding. It must make this limitation explicit in UI help/known limitations rather than faking source text changes.

Add view-model and renderer-adapter tests where practical. Keep WPF rendering tests semantic; do not write fragile pixel tests.

## Acceptance criteria
- User can compare two actual text files in a single tab.
- Inserted/deleted/modified blocks are visually distinct.
- Scroll synchronization behaves safely for different-length files and does not recursively fight itself.
- Editing a pane marks the comparison stale and disables merge/navigation until recompare.

## Drift prevention
No intraline highlighting, minimap, syntax profiles, virtual padding, or 3-way UI.

## Mandatory completion evidence
- Add/update automated tests for the change.
- Run Debug and Release build/test commands.
- Create the required development report under `docs/task-reports/`.
- Do not start the next task until the paired testing task has passed.
