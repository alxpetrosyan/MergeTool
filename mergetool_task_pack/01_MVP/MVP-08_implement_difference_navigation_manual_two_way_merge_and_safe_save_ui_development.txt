# MVP-08 Development Task
## Headline
Implement navigation, manual 2-way merge commands, and safe-save UI


## Objective
Finish the core manual merge workflow for text files.

## Developer instructions
Implement in Application:
- `DifferenceNavigator` over non-equal blocks, using stable block IDs and explicit no-wrap behavior for MVP.
- current difference selection and scroll request generated through the presentation map.
- `ManualTwoWayMergeService` that accepts a valid `MergePrecondition` and can copy the current hunk left-to-right or right-to-left.
- precise behavior for each block kind:
  - Modified: replace target range with source block lines.
  - Inserted: insert source lines into target at the planned anchor.
  - Deleted: delete target range so target matches absence on source.
- merge source text must be normalized to the target document's line-ending convention; preserve target encoding on save.
- after a successful merge, mutate only target session, increment target revision, mark target dirty, mark comparison stale, and require recompare before another merge.
- if merge precondition no longer matches, refuse and explain why.
- save left, save right, save all commands using `SafeTextFileWriter`.
- close-tab/application confirmation for dirty documents. `Save` conflict presents Cancel/Reload only in MVP; no force overwrite.

UI:
- next/previous difference
- copy current change to left/right commands with direction availability based on read-only/stale/no-result state
- dirty indicators and safe error feedback

Automated tests must assert exact document text for modified/inserted/deleted hunks in both directions, stale-precondition rejection, no-wrap navigation, safe-save conflict, and line-ending output.

## Acceptance criteria
- A user can manually make one document match the selected hunk from the other, recompare, and save it safely.
- Merge commands never operate on stale result/document revisions.
- Closing with dirty text asks for a safe decision.

## Drift prevention
No multi-select merge, automatic merge, insert-before/after variants, force overwrite, or 3-way output mode.

## Mandatory completion evidence
- Add/update automated tests for the change.
- Run Debug and Release build/test commands.
- Create the required development report under `docs/task-reports/`.
- Do not start the next task until the paired testing task has passed.
