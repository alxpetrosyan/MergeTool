# MVP-09 Development Task
## Headline
Implement recursive 2-way quick folder comparison engine with accurate states


## Objective
Produce a safe folder comparison result for two roots without claiming metadata equality proves content equality.

## Developer instructions
Implement in `MergeTool.Folders`:
- `FolderComparisonRequest`, `FolderComparisonOptions`, `FolderComparisonResult`, `FolderComparisonRow`, and `FolderRowState`.
- validate roots: both must exist, be directories, and have different normalized full paths.
- recursive scan in background through application orchestration, with cancellation/progress.
- enumerate relative paths using Windows case-insensitive matching while retaining source display casing.
- file rows compare quick metadata only: length plus `LastWriteTimeUtc`.
- valid states exactly: `LeftOnly`, `RightOnly`, `MetadataMatch`, `MetadataDifferent`, `Error`, `SkippedReparsePoint`.
- directory rows may be emitted only when useful for flat navigation/diagnostics; MVP primary UI is a flat recursive file grid.
- do not follow reparse-point directories. Report them with state/diagnostic.
- no hidden default folders/exclusions.
- individual inaccessible files/directories create row diagnostics and do not crash or erase other results.
- use relative paths/path APIs, never manual path string concatenation.
- stable deterministic sort by relative path using Windows ordinal-ignore-case order with ordinal tie-breaker.

Add tests using generated temp trees: metadata match, metadata difference, left/right only, nested paths, case behavior, cancellation, error diagnostics through abstraction, and skipped reparse-point behavior if supported by test environment (otherwise test abstraction behavior).

## Acceptance criteria
- A `MetadataMatch` row is explicitly named/displayable as a quick metadata match, never content-identical.
- Scan does not load file bodies.
- Cancelling leaves a controlled result/status, not a crash or corrupted partial state.

## Drift prevention
No content hash mode, default filter presets, folder copy/delete, folder tree widget, 3-way folders, archive support, or following junctions/symlinks recursively.

## Mandatory completion evidence
- Add/update automated tests for the change.
- Run Debug and Release build/test commands.
- Create the required development report under `docs/task-reports/`.
- Do not start the next task until the paired testing task has passed.
