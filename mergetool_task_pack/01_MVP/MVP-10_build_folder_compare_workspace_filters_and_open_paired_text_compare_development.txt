# MVP-10 Development Task
## Headline
Build folder comparison workspace, filters, and paired text-file opening


## Objective
Expose the quick folder comparison as a usable workflow in the same application shell and connect it to file comparison.

## Developer instructions
Implement Folder Compare workspace with:
- left/right folder pickers and clear root validation messages
- compare/recompare/cancel commands
- flat virtualized result grid with columns: relative path, state, left size/time, right size/time, diagnostics
- visible progress and scan status
- semantic state styles and a legend that explicitly says `Metadata match = size + UTC modification time only`.
- filters: All, Differences, Errors/Skipped. `Differences` includes left-only, right-only, metadata-different, error, skipped—not metadata-match.
- stable sort by relative path and state where supported.
- command `Open paired text comparison` enabled only for rows where both paths exist as files.
- opening a paired comparison must create/reuse a File Compare tab through application workflow; it must not scan/read editor content in code-behind.
- for one-sided rows, show an explicit message that a 2-way file comparison needs both paths; do not invent a blank-file merge mode in MVP.
- for non-text or decoding failures, show diagnostic and do not pretend binary comparison exists.

Add view-model tests for filter states, command enablement, selected row behavior, and tab-opening request construction.

## Acceptance criteria
- User can compare two folders, filter results, and open a real paired file comparison from a row.
- UI labels cannot mislead users about quick comparison certainty.
- Large grids use WPF virtualization settings where available.

## Drift prevention
No embedded file preview, folder copy/delete, tree mode, content hashing, or auto-refresh file watcher.

## Mandatory completion evidence
- Add/update automated tests for the change.
- Run Debug and Release build/test commands.
- Create the required development report under `docs/task-reports/`.
- Do not start the next task until the paired testing task has passed.
